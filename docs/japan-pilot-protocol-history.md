# 일본 1회 실증 문항 변경 기록

## 현재 확정안: `jp-first-meeting-2.0` (2026-10-26)

사용자가 제공한 최종 문구로 본질문 9개와 후속 질문 5개를 교체했습니다. 일본어·한국어는 제공 문구를 유지하며 영어도 같은 내용으로 맞춥니다. 실행 문항의 기준은 `src/features/pilot/pilotProtocol.ts`, 일본어 한 줄·한국어 한 줄 안내서는 [확정 문항 문서](japan-first-meeting-pilot-ja-ko.md)입니다.

| 번호 | 방식 | 확정 주제 | 정답·진행 |
| --- | --- | --- | --- |
| Q1 | 4지선다 | 오늘의 요일 | 일본 날짜의 실제 요일 포함, 중복 없는 오답 3개, 보기 무작위 |

- 목표 시간은 8~10분입니다. 도입 30초·선택형 165초·음성 375초·종료 20초를 배분해 약 9분 50초로 잡았습니다. 동의 설명 시간은 제외하며 세션 강제 종료는 없습니다.
- 음성은 문항당 45~90초를 목표로 하되 자연스러운 발화를 우선합니다. 이전의 60초 녹음 상한은 180초로 늘렸습니다.
- 본질문을 저장한 뒤 기본 `다음`은 다음 문항으로 이동합니다. 진행자가 짧은 답변이라고 판단할 때만 화면의 `후속 질문하기 (진행자)`로 준비된 질문을 한 번 사용합니다. 자동 전사나 발화 길이 자동 판정은 없습니다.
- 후속 질문 사용 여부·이유·판단 시각·응답 또는 거절 사유를 남깁니다. 후속 질문 거절은 본질문 답변을 지우지 않습니다. 기억이 나지 않거나 불편한 문항은 건너뛸 수 있고 가족 질문에 답변을 강요하지 않습니다.
- 각 회차에 Q1 일본 날짜·시간대·생성 시각·실제 보기·정답을 고정합니다. 다시 그리거나 나중에 내보내도 바뀌지 않습니다. 이전 회차의 문항 버전이나 배열을 덮어쓰는 서버 저장 요청도 거절합니다.
- 원본 음성·중간 녹음·재녹음·선택 변경·정오답·응답 시간·체류·이탈 기록을 계속 수집합니다. 한 번 시작할 때마다 새 UUID·회차를 만들며 동일 참가자 번호의 기록을 보존합니다.
- 동의 문구 버전은 `jp-pilot-consent-2.0`입니다. PC 저장 동의와 이후 전사·명시된 기억 저장 및 개인화 활용 동의를 구분합니다. 이전 동의를 새 범위로 소급 변경하지 않습니다. 내보내기의 `memoryTranscriptionEligible`은 새 범위의 명시적 동의가 있을 때만 참입니다.
- 개인 기억 RAG 활용은 후속 작업입니다. 현재 앱은 자동 전사나 외부 전송을 하지 않습니다. 동의한 전사에서 명시적으로 언급한 인물·장소·직업·활동·사건·취향만 발화 근거와 함께 추출하며, 미언급 사실이나 Q4 가상 인물을 참가자 사실로 만들지 않습니다.
- 본 실증은 인지 활동 응답과 개인 기억 수집 가능성을 관찰하며 임상적으로 검증된 치매 선별검사·진단 도구로 해석하지 않습니다.

## 내보내기 스키마 2

`sessions.json`의 각 회차에 `protocolVersion`, `protocolSnapshot`, 언어별 `administeredQuestions`가 있습니다. Q번호만으로 내용이나 정답을 추정하지 않습니다. 버전 또는 Q1 보기 배열이 다르면 `questionCatalogScope: per-session`, 최상위 `questions: []`로 표시하고 회차별 정의를 사용합니다. 모두 동일한 스냅샷일 때만 최상위 질문 목록을 공통으로 제공합니다.

`attempts.csv`에는 문항 버전과 문항 수, `questions.csv`에는 선택·정오답·응답 시간·후속 질문 상태, `events.csv`에는 문항 버전을 추가했습니다. 오디오 파일 경로·원본 바이트·이전 SQLite 데이터 구조는 보존합니다. 구버전 JSON을 분석하는 별도 코드가 있다면 스키마 2의 회차별 문항 기준으로 확인합니다.

## TTS 제작 목록과 이전 시제품

[TTS 제작 목록](japan-pilot-tts-inventory.json)은 버전 2용입니다. 본질문 9개, 조건부 후속 질문 5개, 선택지 음원 19개, 공통 안내 16개로 49개 항목입니다. 선택지 음원은 Q1 요일 7종과 Q2~Q4 보기 12개이며, 실제 Q1에서는 해당 회차의 네 요일만 표시 순서로 조합합니다. 49개를 한 참여자에게 전부 재생한다는 뜻이 아닙니다.

화자는 이전과 같은 Fish Audio `女性アナウンサー（ベテラン）` / `veteran`입니다. 2026-10-26 BrowserOS neo에서 표시된 화자 페이지는 `https://fish.audio/app/m/f1d92c18f84e47c6b5bc0cebb80ddaf5`, 모델 표시명은 `Fish Audio Drama 3`였습니다. 화자 페이지 ID를 생성 API 모델 ID로 간주하지 않습니다.

이전 Q1 `今日の気分はいかがですか。`는 자동 태그 `[丁寧で穏やかな口調]`와 `[short pause]` 두 번으로 생성했고, 후보 두 개를 모두 내려받아 MP3 전체 디코딩을 확인했습니다. 원본과 메타데이터는 로컬 `local-data/tts-samples/ja/q01-veteran-20261026-1511/`에 남습니다. **기분 질문은 버전 2에서 제거됐으므로 두 파일은 현재 Q1 요일에 연결하지 않습니다.** 9문항용 Fish 음원은 아직 생성·연결하지 않았으며 현재 재생은 브라우저 읽어주기입니다.

## 이전 버전: `jp-first-meeting-1.0`

이전 세트는 기분·어린 시절·오래 해 온 일·장보기·주변 사람·공유 추억·속담·요즘 즐거움·음식·도형·최근 경험·앞으로의 바람의 12문항이었습니다. 선택형 4개와 음성 8개를 섞었고 모든 음성 문항에 본질문과 후속 녹음을 요구했습니다. 이 구성은 새 회차에서 사용하지 않습니다.

이전 999번 테스트와 수집 회차는 당시 문항 스냅샷·동의·원본 녹음·이벤트와 함께 보존합니다. 브라우저의 이전 버전 기록도 새 버전 번호로 필터링해 숨기지 않습니다. 이전 기록을 현재 9문항으로 바꾸거나 과거 질문의 이름을 새 내용으로 덮어쓰지 않습니다. Raspberry Pi 별도 앱과 기존 일일 루틴·과거 Fish 제작 기록은 이 문항 개편 대상이 아닙니다.

## 검증 기록

이전 버전에서는 Node.js 24.20.0·npm 11.19.0으로 별도 작업 폴더와 GitHub 재clone의 설치·빌드를 확인했고, 저장 폴더 이동과 구형 절대 경로 음성 호환을 포함한 저장 테스트 7개·관련 프론트엔드 68개가 통과했습니다. 이는 이전 버전 검증입니다.

현재 버전은 `npm run test:pilot`의 로컬 저장 8개·문서 동기화 1개·프론트엔드 75개, 총 84개가 통과했습니다. 실증용 빌드(타입 검사 포함), 변경 TS/TSX ESLint, 변경 Node 스크립트 구문 검사와 `git diff --check`도 통과했습니다.

BrowserOS neo에서 격리된 테스트 저장 폴더를 사용해 999번 1회차의 9문항을 완료했습니다. 선택 변경, 후속 질문 사용·생략·거절, 재녹음을 확인했고, 원본 녹음 7개·이벤트 151개가 들어간 ZIP을 내려받았습니다. ZIP CRC·원본 바이트 일치·모든 녹음의 전체 디코딩이 확인됐습니다. 같은 번호의 2회차는 새 UUID로 Q1부터 시작했고 이전 완료 회차는 보존됐습니다. 검증의 자세한 근거와 한계는 [현재 버전 검증 기록](japan-pilot-v2-verification.md)에 있습니다.

브라우저 녹음 검증에는 Web Audio 합성 신호를 사용했습니다. 현장 PC의 실제 마이크·권한·일본어 발음·음량과 실사용 8~10분 여부는 별도 현장 확인 대상입니다.
