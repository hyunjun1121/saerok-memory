# Welfare Center / Hybrid Usage Plan (SP-15)

작성일: 2026-06-23

복지관·지자체 운영 시나리오와 “복지관에서 하고 집에서 이어하는 하이브리드” 모델의 설계 방향을 정리한다. 현재 앱은 개인 브라우저 `localStorage` 기반 MVP이므로, 서버·계정·실시간 집계가 필요한 항목은 별도 범위로 남긴다.

## 운영 모드 구분

1. **개인 스마트폰 모드**: 기존 `/` 홈에서 오늘 루틴을 시작. 개인 `localStorage`에 기억 카드·활동 기록·스트릭·정원 상태 저장.
2. **복지관 태블릿/키오스크 모드**: `/kiosk` 라우트(1차 구현). 큰 글자·큰 버튼·한 화면 한 버튼. 익명/로컬 데모로 제한.
3. **집 연계 복습 모드**: 복지관에서 시작한 루틴을 집에서 이어하는 흐름(향후 계정/동기화 도입 시 설계).

## 개인정보 축적 방식(후보, P2)

- 익명 시작(기본): 개인 식별 없이 로컬 데모.
- 카드/QR 로그인: 명시적 로그인 이후에만 개인 기록 축적.
- 모든 방식은 명시적 동의·삭제·접근 통제가 전제되어야 한다.

## 운영자 요약 범위

운영자(복지관 직원)가 보는 데이터는 **참여 운영 데이터** 중심이며, 개인 인지 수행 원자료와 분리된다.

- 참석자 수
- 완료 수
- 평균 소요 시간
- 보상 수령 여부(운영기관이 별도 관리)

개인의 인지 수행 점수·오류 패턴은 운영자 대시보드에 노출하지 않는다.

## 현재 구현 상태

- `/kiosk` 라우트 + `KioskHomeScreen`(큰 CTA, 오늘 루틴 이름, `useKioskControls` 키보드/물리버튼 입력) 추가됨.
- `useKioskControls`: Enter/Space 주요 버튼 실행, 숫자 1-4 선택.
- 익명/로컬 데모로 제한(자동 로그인·카드 로그인 미구현).

## 남은 과제

- 운영자 요약 화면(`StaffSummaryScreen`) 및 익명 집계 구조.
- 카드/QR/자동 로그인 흐름.
- 복지관 보상 카탈로그 운영자 설정 UI(`weeklyRewards.ts`의 카탈로그 데이터 구조는 준비됨, 실제 지급/재고는 별도 범위).
- 서버 동기화는 MVP 범위 밖.
