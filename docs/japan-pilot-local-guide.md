# 일본 실증용 웹앱 설치·운영 가이드

갱신: 2026-10-26. 이 문서는 저장소의 `japan-pilot` 브랜치, 루트 React 웹앱 `/pilot`, Node.js 로컬 수집 서버를 설명합니다. Raspberry Pi 전용 앱과 일일 루틴용 STT·RAG 서버는 별도입니다.

## 새 컴퓨터에서 처음 실행

Git, **Node.js 24.x와 npm 11 이상**, 마이크, 녹음이 가능한 Chrome 또는 Edge를 준비합니다. `node --version`이 `v24.`로 시작하는지 확인합니다. 설치·의존성 다운로드에는 인터넷이 필요합니다. Python, GPU, API 키, STT·RAG 설치, 별도 SQLite 설치는 필요하지 않습니다.

PowerShell, macOS/Linux 터미널에서 같은 순서로 실행합니다. 명령이 실패하면 다음 명령으로 넘어가지 말고 오류를 먼저 해결합니다.

```sh
git clone --branch japan-pilot --single-branch https://github.com/hyunjun1121/saerok-memory.git
cd saerok-memory
node --version
npm --version
npm ci --include=dev --include=optional --no-audit --no-fund
npm run start:pilot
```

브라우저에서 **http://127.0.0.1:5188/pilot**을 엽니다. `start:pilot`는 실행 환경 확인, 실증용 빌드, 수집 서버 시작을 차례로 수행합니다. 터미널은 실증이 끝날 때까지 열어 둡니다. 종료는 해당 터미널에서 `Ctrl+C`입니다. 이미 빌드한 뒤 다시 켤 때는 `npm run preview:pilot`만 실행해도 됩니다.

저장소 접근을 위한 GitHub 로그인이 필요한 경우 Git의 로그인 안내를 따릅니다. `.env.japan-pilot`은 비밀값이 없는 일본어 실증 설정으로 저장소에 포함됩니다. 새 `.env` 파일이나 키를 만들 필요가 없습니다.

`japan-pilot` 브랜치를 지정하지 않은 clone은 기본 `main`을 받습니다. 기존 clone에 저장할 변경 사항이 없다면 다음을 사용합니다. 작업 중인 변경이 있다면 위 명령으로 다른 폴더에 새 clone을 만듭니다.

```sh
git fetch origin japan-pilot
git switch japan-pilot
git pull --ff-only origin japan-pilot
npm ci --include=dev --include=optional --no-audit --no-fund
npm run start:pilot
```

## 실행 명령 구분

| 목적 | 명령 | 설명 |
| --- | --- | --- |
| 처음 실행·업데이트 후 실행 | `npm run start:pilot` | 실증용으로 빌드한 뒤 로컬 수집 서버 실행 |
| 빌드한 앱 재실행 | `npm run preview:pilot` | 기존 `dist/` 사용. 직전 빌드가 `build:pilot`여야 함 |
| 문구·코드 개발 | `npm run dev:pilot` | Vite와 수집 서버 함께 실행. 수집 중 자동 새로고침을 막기 위해 HMR 비활성화 |
| 환경 확인 | `npm run check:pilot` | Node.js 24와 내장 SQLite 확인 |
| 실증 기능 검증 | `npm run test:pilot` | 로컬 저장 및 실증 UI·음성·라우팅·문구 관련 테스트 |
| 문항·TTS 제작 문서 갱신 | `npm run docs:pilot` | 문항 정의에서 일·한 문서와 TTS 제작 목록 생성 |

`npm run dev`, `npm run preview`, 정적 파일만 여는 방식은 실증 수집 서버를 시작하지 않습니다. 실증에는 위 `:pilot` 명령을 사용합니다. `dev:local`은 기존 일일 루틴의 STT·RAG 실행 명령입니다.

일본어가 기본입니다. 한국어 검토는 `http://127.0.0.1:5188/pilot?lang=ko`, 영어 검토는 `?lang=en`을 사용합니다. 수집하는 동안에는 URL, 포트, 브라우저 프로필을 유지합니다. `localhost`와 `127.0.0.1`은 브라우저 저장 영역이 서로 다릅니다.

## 참가자 한 명 진행하기

1. 시작 화면에서 참가자 번호를 선택합니다. 버튼은 1~6이며 입력란에는 1~99999를 입력할 수 있습니다. `001`은 `1`로 취급합니다. 실명 대신 번호를 사용합니다.
2. 진행자가 녹음·응답·조작 기록의 PC 저장 동의를 확인합니다. 후속 개인화 활용 동의는 별도이며 기본값은 해제입니다. 같은 번호라도 매 회차 동의를 다시 확인합니다.
3. 시작하면 새 UUID와 새 회차가 생성됩니다. 같은 사람이 돌아와도 같은 번호를 선택하고 **1번 문항부터 새 회차**로 수집합니다. 기존 회차와 중간 녹음은 보존합니다.
4. 고정 12문항을 진행합니다. 4지선다 4개와 음성 8개이며 음성은 본질문과 후속 질문을 따로 녹음합니다. 목표 약 10분은 안내 기준이며 강제 종료 타이머가 아닙니다.
5. 완료 화면에서 저장 상태를 확인하고 현재 회차 ZIP을 내려받습니다. 시작 화면에서 저장된 전체 회차를 ZIP으로 내보낼 수도 있습니다.
6. `다음 참가자 준비`로 시작 화면으로 돌아가 다음 번호를 지정합니다. 실수로 창을 닫았어도 같은 번호로 다시 시작하면 이전 회차를 덮어쓰지 않습니다.

2×2 버튼은 왼쪽 위 `1/A/빨강`, 오른쪽 위 `2/B/노랑`, 왼쪽 아래 `3/C/초록`, 오른쪽 아래 `4/D/파랑`입니다. USB 버튼은 키보드 숫자 1~4를 보내도록 설정합니다. 터치·마우스도 가능합니다.

선택형은 한 번 눌러 선택하고 같은 버튼을 다시 눌러 확정합니다. 음성은 오른쪽 `2/4`로 시작·정지·저장 후 다음 이동, 왼쪽 `1/3`으로 다시 듣기·재녹음합니다. 건너뛰기에는 이유를 남깁니다. 녹음 한 번의 상한은 60초이며 재녹음 전 원본도 남습니다.

## 저장 위치와 파일

기본 위치는 **현재 프로젝트 폴더 아래** `local-data/japan-pilot/`입니다. 실행 터미널과 시작 화면에도 실제 절대 경로가 표시됩니다.

```text
local-data/japan-pilot/
  pilot.sqlite
  pilot.sqlite-wal / pilot.sqlite-shm  (실행 중 생길 수 있음)
  participants/
    1/
      attempt-001-<session UUID>/
        session.json
        audio/                       (정상 종료한 원본 녹음)
        chunks/<recording UUID>/     (중간·미완료 녹음 조각)
      attempt-002-<다른 UUID>/
```

SQLite가 참가자·회차·응답·전체 이벤트·녹음 목록의 기준입니다. `session.json`은 회차별 응답 요약이며 전체 이벤트 로그를 대신하지 않습니다. `participants/`만 복사하면 전체 분석 데이터와 회차 관리 정보가 빠집니다.

문항 진입·이탈, 전체 체류 시간과 화면 표시·포커스가 있는 체류 시간, 선택·변경·확정, 녹음·재녹음·미리 듣기, 창 숨김·포커스·연결 상태·기기 환경을 기록합니다. 녹음은 약 1초 단위 조각을 로컬 서버로 보내며, 전송 대기는 브라우저 IndexedDB에 보관해 재시도합니다. 강제 종료 직전의 미전송 구간은 누락될 수 있습니다. 종료 신호가 없으면 마지막 확인 시각과 마지막 문항을 남기며 정확한 이탈 시점으로 단정하지 않습니다.

| ZIP 파일 | 내용 |
| --- | --- |
| `sessions.json` | 문항 원문 스냅샷, 동의, 회차, 선택 응답, 녹음·이벤트 정보 |
| `attempts.csv` | 참가자·회차별 상태와 요약 |
| `questions.csv` | 본질문·후속 질문별 체류 시간과 조작 요약 |
| `events.csv` | 전체 원시 이벤트 |
| 오디오 파일 | 재녹음 전 파일과 보존된 미완료 녹음을 포함한 원본 |

이 실증 흐름에서는 자동 전사, Microsoft·Meta·Fish Audio로의 참가자 답변 전송, 자동 인물 프로필 추정을 실행하지 않습니다. 이후 전사와 개인화는 별도 처리입니다. 현재 안내는 브라우저 읽어주기를 사용하며, 기존 Fish 음원은 아직 실증 화면에 연결하지 않았습니다. 새 녹음 안내의 제작 목록은 [TTS 설계 문서](japan-pilot-tts-plan-ja-ko.md)에 있습니다.

## 백업·다른 PC로 데이터 이동

Git clone은 **코드와 안내용 기존 정적 자산**을 가져옵니다. 실증 데이터, 원본 답변 녹음, 999번 테스트 기록은 Git에 올라가지 않으며 새 PC에서는 빈 상태로 시작합니다. 두 PC에서 같은 번호를 입력해도 데이터가 자동으로 합쳐지지 않습니다.

실행 중에는 화면의 ZIP 내보내기로 백업합니다. 전체 데이터 이동은 다음 순서입니다.

1. 녹음을 마치고 저장 오류가 없는지 확인합니다. 같은 브라우저·주소로 수집 서버에 연결한 상태에서 ZIP 내보내기가 성공하는지 확인합니다. 서버가 내려가 있다면 같은 주소와 포트로 먼저 다시 켜 전송 대기를 처리합니다.
2. 해당 서버 터미널에서 `Ctrl+C`로 종료합니다.
3. **`local-data/japan-pilot` 폴더 전체**를 안전한 저장장치로 복사합니다. SQLite와 존재하는 WAL/SHM, `participants`를 함께 보관합니다. 실행 중 DB 파일만 복사하지 않습니다.
4. 새 PC에 코드를 clone·설치한 뒤, 서버를 실행하기 전에 백업 폴더 전체를 새 프로젝트의 `local-data/japan-pilot`에 둡니다. 기존 데이터가 있는 폴더에 겹쳐 복사하거나 DB를 수동 병합하지 않습니다.
5. `npm run start:pilot`로 켜고 기존 번호의 회차 목록과 ZIP을 확인합니다. 같은 번호를 시작하면 다음 회차가 새로 만들어집니다.

ZIP은 분석·보관용 내보내기이며 현재 앱에는 ZIP 가져오기 기능이 없습니다. 이어서 회차를 관리하려면 전체 저장 폴더를 이동합니다. 브라우저에만 남은 미전송 데이터는 Git이나 폴더 복사로 이동하지 않으므로 원래 PC에서 전송을 먼저 마칩니다.

별도 위치에 저장하려면 실행하는 터미널마다 환경 변수를 설정합니다. 이 값은 서버용이며 `VITE_`를 붙이지 않습니다. 한 저장 폴더에는 서버 하나만 연결합니다.

Windows PowerShell:

```powershell
$env:HARU_PILOT_DATA_DIR = 'D:\HaruPilotData'
npm run start:pilot
```

macOS/Linux:

```sh
HARU_PILOT_DATA_DIR="$HOME/HaruPilotData" npm run start:pilot
```

저장 위치는 처음부터 정하고 매번 동일하게 설정합니다. 변경하면 이전 폴더의 데이터가 자동 이동하지 않습니다. 참가자 번호와 실명 대응표, ZIP과 별도 백업은 진행자가 별도로 관리합니다. 앱에서 회차를 삭제해도 이미 내보낸 ZIP이나 복사본은 지워지지 않습니다.

## 현장 확인과 문제 해결

| 증상 | 확인·조치 |
| --- | --- |
| Node/SQLite 오류 | `node --version` 확인. Node.js 24.x 설치 후 터미널을 다시 열고 `npm ci` 재실행 |
| PowerShell이 `npm.ps1`을 차단 | `npm` 대신 `npm.cmd`로 같은 명령 실행. 예: `npm.cmd run start:pilot` |
| 포트 5188 사용 중 | 기존 Haru 서버 터미널부터 확인. 모르는 프로세스를 종료하지 말고 필요하면 `npm run preview:pilot -- --port 5189` 사용. 이후 해당 포트를 계속 유지 |
| 페이지는 열리지만 저장 실패 | `:pilot` 명령으로 서버를 실행했는지, 터미널이 열려 있는지, 저장 폴더 쓰기 권한과 디스크 여유가 있는지 확인. 같은 주소에서 다시 저장 |
| 마이크 녹음 실패 | 브라우저의 해당 사이트 마이크 권한, OS 마이크 접근 허용, 입력 장치 선택 확인. 다른 앱이 장치를 점유하는지도 확인 |
| 일본어 안내가 안 들림 | 현재 브라우저·OS의 일본어 읽어주기 환경과 음량 확인. 없으면 진행자가 동일한 문구를 읽음. 새 Fish 음원 제작·연결은 별도 작업 |
| 코드 업데이트가 보이지 않음 | 참가자 진행을 마친 뒤 서버 종료 → `git pull --ff-only origin japan-pilot` → `npm ci` → `npm run start:pilot` → 브라우저 새로고침 |
| 다른 기기에서 주소가 안 열림 | 이 서버는 같은 PC의 `127.0.0.1`에만 열림. 다른 PC/태블릿은 각자 clone·실행. LAN 공개 실행은 이 안내 범위에 포함하지 않음 |

새 현장 PC에서는 테스트 번호 **999**로 실제 마이크를 사용해 끝까지 진행하고, 재녹음·다시 듣기·ZIP 속 음성 재생까지 확인합니다. 기존 개발 PC의 합성 음성 테스트 통과는 새 PC의 마이크 권한·장치·일본어 발음을 확인한 결과가 아닙니다. 테스트 번호는 실증 참가자에게 배정하지 않습니다.

설치 후 로컬 서버는 답변 수집에 외부 API를 요구하지 않습니다. 화면 글꼴 CDN이나 OS·브라우저 읽어주기의 네트워크 사용 여부는 환경에 따라 다르므로 인터넷을 끊을 현장이라면 그 상태로 미리 실행해 확인합니다.
