## 핵심 제품 판단

Haru는 정식 치매 검사 앱이 아니라, 고령 사용자가 매일 부담 없이 수행하는 인지·기억 루틴과 보호자/상담사 대화 준비 리포트를 제공하는 서비스로 유지한다.

다만 방향성은 과도하게 방어적으로 두지 않는다. 신뢰 가능한 의료·인지과학 자료를 바탕으로 Haru 자체의 위험도·주의도 평가 체계를 설계하고, 반복 사용 데이터와 보호자 관찰을 조합해 실질적으로 도움이 되는 판단을 제공하는 방향이 맞다. 핵심은 “아무 판단도 하지 않는 것”이 아니라, 공식 의학 지표인 것처럼 오인되지 않게 표시하면서도 Haru가 합리적으로 산출할 수 있는 정보는 충분히 제공하는 것이다.

프로그램 시작 또는 첫 사용 시에는 다음 취지의 안내가 필요하다.

- Haru의 결과는 일상 인지 루틴과 대화 준비를 돕기 위한 참고 정보이다.
- Haru의 자체 위험도·주의도는 의학적 진단, 공식 선별검사 결과, 치료 또는 예방 효과를 의미하지 않는다.
- 걱정되는 변화가 반복되거나 가족·보호자가 우려를 느끼면 전문 의료진과 상담해야 한다.

따라서 참고자료는 다음 용도로만 사용한다.

- 공식 검사 전체를 복제하지 않고, 하위 인지 영역을 Haru식 짧은 활동으로 재설계한다.
- 결과는 반복 참여 기록, 반응 경향, 회상 단서, 보호자 대화 주제, Haru 자체 위험도·주의도 평가로 표현할 수 있다.
- 사용자 화면은 친근하고 짧은 루틴 중심으로 유지한다.
- 보호자/상담사 화면은 활동 요약, Haru 자체 주의도, 대화 준비 자료, 전문 상담 권유 조건을 제공할 수 있다.
- 장기적으로는 전문가 자문과 별도 임상 검증 전까지 외부 규준, 백분위, 공식 절단점, 병명 추정, 공식 선별 양성/음성 판정을 UI에 넣지 않는다.

| NCPT/Zenodo 공개 데이터 | 오프라인 분석, 데모 리포트 패턴 설계, 데이터 구조 학습, 내부 실험용 기준선 탐색, Haru 자체 위험도 모델 설계 참고 | 외부 인구 규준, 백분위, 임상 판정을 Haru 사용자에게 직접 적용한 것처럼 표시 |
| 공개 GitHub 저장소 | 터치 흐름, 반응시간 기록, TMT/Stroop/그리기 구현 패턴 참고 | 임상 검증된 코드처럼 취급하거나 라이선스 확인 없이 복사 |
| 저장 HTML과 `not_downloaded` 기록 | 접근 제한 또는 대체 근거 상태를 기록하고 출처 추적에 사용 | 다운로드하지 못한 PDF를 확보한 것처럼 설명 |

## 우선 적용할 기능 방향

| 우선순위 | 기능 방향 | 근거 연결 | Haru식 구현 결정 |
| --- | --- | --- | --- |
| 1 | 보호자/상담사 관찰 입력 | AD8, GPCOG informant 흐름, TICS/GPCOG식 원격·보호자 정보 결합 | `CaregiverObservationRecord`처럼 최근 변화 영역을 저장하고, 리포트에는 대화 준비 주제, 상담 전 확인할 항목, Haru 자체 주의도 산출 근거로 변환한다. 공식 문항과 점수는 쓰지 않는다. |
| 2 | 지연 단어 회상 | Five Word Test, MoCA/SLUMS/MMSE의 지연회상 하위 영역 | Haru 자체 단어 세트와 범주 단서를 사용한다. 먼저 떠올리기 입력을 받고, 이후 재인 선택을 제공한다. 정답 개수와 지연 시간을 내부 metadata로만 저장한다. |
| 3 | 숫자 순서·역순 기억 | Digit Span 계열 | 공식 WAIS 문항이 아니라 짧은 자체 숫자열을 사용한다. 최대 span 진단이 아니라 일일 활동 기록으로만 저장한다. |
| 4 | 의미 유창성 | Category verbal fluency 문헌 | 동물, 과일, 장보기 품목 같은 문화적으로 쉬운 범주를 사용한다. 60초 자유 발화 또는 입력을 지원하되, 언어·교육 편향 때문에 점수 판정은 하지 않는다. |
| 5 | 터치형 색상 집중 루틴 | Stroop 관련 문헌과 공개 구현 참고 | `stroop_touch_practice`로 먼저 구현한다. 화면에는 단어 뜻보다 잉크 색을 고르는 활동으로 제시하고, 반응시간·오답 수를 metadata로 저장한다. 장기 변화는 Haru 자체 주의도에 반영할 수 있지만, 공식 Stroop 명칭·간섭점수·규준은 쓰지 않는다. |
| 6 | TMT-lite 연결 루틴 | TMT, digital TMT, set-shifting 문헌 | 숫자/도형을 차례로 누르는 Haru식 짧은 연결 활동으로 구성한다. 공식 TMT-A/B 형식과 채점 기준을 복제하지 않는다. |
| 7 | 그리기·시공간 루틴 | Clock drawing, dCDT, 도형 복사 문헌과 공개 코드 참고 | 공식 시계그리기 지시·채점 대신 단순 도형 따라 그리기, 획 수, 첫 터치 지연, 그리기 시간, 멈춤 횟수, 지우기 횟수, 터치 경로를 기록한다. |
| 8 | 개인 기억 회상·재확인 | 회상 기반 정서 지원과 지연 재인 원리 | 사용자가 말하거나 입력한 구체적 일상 기억을 구조화된 memory card로 저장하고, 이후 대화형 회상·재인 질문과 보호자 대화 주제로 연결한다. 공유는 명시적으로 허용된 카드만 사용한다. |

## 이미 반영된 결정

- **Haru 자체 인지 루틴 및 보호자 관찰 기능이 전원 구현 및 통합되었습니다.**
- `stroop_touch_practice` (색상 집중 루틴), `digit_span_practice` (작업기억 연습), `verbal_fluency_practice` (언어 유창성 연습), `trail_switching_practice` (주의 전환 연습), `orientation_practice` (날짜 감각 연습), `shape_copy_practice` (도형 그리기 연습), `delayed_word_recall` (5단어 지연회상)이 구현되었습니다.
- 모든 기록은 `cognitiveRoutineResults`, `caregiverObservationRecords`, `memoryCards` 형태로 `localStorage`에 구조화된 메타데이터와 함께 저장됩니다.
- 보호자 및 상담사 대화 준비 리포트가 완성되었으며, `/family` 경로에서 보호자 관찰 기록, 참여율, 트렌드, 활동 단서(highlights), 강점(strengths), 비대면 대화 소재(conversation cues)를 가시적으로 출력합니다.
- 전체 유닛 및 컴포넌트 검증 결과, 25개 파일 및 76개 테스트 케이스가 성공적으로 통과하였습니다.

## 코드 작업 체크리스트

- 새 인지 루틴은 `src/data/mockExercises.ts`의 `ExerciseType`과 `ExercisePayload`를 먼저 확장한다.
- 새 화면은 `src/features/lessons/ExerciseRenderer.tsx`에 등록한다.
- visible text는 `src/locales/ko.json`, `src/locales/ja.json`, `src/locales/en.json`에 모두 추가한다.
- 새 metadata는 `src/features/cognitive/cognitiveRoutineStorage.ts`의 타입과 호환되게 저장한다.
- 보호자/상담사 리포트에 연결할 때는 private memory detail을 직접 노출하지 않는다.
- `shareWithFamily === true`인 기억 카드만 구체적 대화 주제로 쓴다.
- tests는 최소한 렌더링, localStorage 저장, 리포트 변환, 비진단 문구 유지 여부를 확인한다.

## 근거 추적 규칙

- 제품·지원서·README에 들어가는 외부 사실은 `metadata/download_manifest.csv`의 `source_url`, `local_path`, `status`, `notes` 중 하나로 추적 가능해야 한다.
- `report_url_coverage.csv`에서 `not_downloaded`인 항목은 “원문 PDF 확보”라고 쓰지 않는다.
- PubMed/OpenAlex 메타데이터만 있는 항목은 초록·서지 수준 근거로만 사용하고, 본문 수치나 결론을 단정하지 않는다.
- 상용 검사·공식 도구는 기능 설계의 “참고 축”으로만 언급하고, 제품 구현의 직접 복제 근거로 쓰지 않는다.

## 중단하고 사용자에게 확인해야 하는 경우

- 공식 검사 문항, 공식 점수표, 절단점, 병명 판정 UI를 넣으라는 요청이 들어온 경우
- 가족/보호자에게 비공개 memory card 내용을 보여줘야 하는 요구가 생긴 경우
- 실제 의료기관, 전문가, 임상검증, 사용자 수, 성과 지표를 주장해야 하는 경우
- 백엔드 저장, 계정, 가족 공유, 원격 상담 등 개인정보 범위가 커지는 구현을 시작하는 경우
- 일본어·한국어 문화권에서 부적절할 수 있는 단어 세트나 질문 세트를 확정해야 하는 경우

위 조건이 아니고, 기존 방향과 안전 원칙에 맞는 범위라면 합리적 가정을 명시하고 구현을 진행한다.
