## 1. 새 계획의 목적

기존 지원서 작성용 계획은 완료된 작업으로 간주하고, 이 문서는 다음 두 가지 후속 목표를 실행하기 위한 새 마스터 플랜으로 사용한다.

1. Haru 구현체를 전체 기능, 테스트, 브라우저 동작, 접근성, 국제화, 이미지 자산, 개인정보, 의료 안전 표현까지 종합 검증하고 필요한 개선을 모두 수행한다.
2. Haru가 어떤 연구적 참고문헌과 공개 자료를 바탕으로 설계되었고, 그 근거가 실제 구현에 어떻게 반영되었는지 하나의 신빙성 있는 보고서로 정리한다.

이 문서는 신청서 본문 작성 계획이 아니다. 이후 작업자가 이 계획을 기준으로 코드 개선, QA, 보고서 작성, 최종 검증을 진행한다.

## 9. 연구 근거 보고서 권장 구성

보고서 제목 후보: `Haru 연구 근거 및 구현 신빙성 보고서`

1. 요약
   - Haru의 목적, 대상 사용자, 현재 구현 범위, 비진단 원칙을 1쪽 내외로 정리한다.
2. 문제 배경
   - 한국과 일본의 고령화, 인지 건강 관리, 가족/보호자 관찰 부담을 근거 중심으로 설명한다.
3. 설계 원칙
   - 매일 짧게, 부담 없이, 클릭 중심, 보상 기반, 개인 기억 중심, 보호자 대화 지원.
4. 참고문헌과 설계 반영
   - 지연 회상, 주의 전환, 작업기억, 언어 유창성, 그리기, 지남력, 보호자 관찰, 접근성 영역별로 정리한다.
5. 구현 근거
   - 각 인지 루틴과 리포트 기능을 실제 파일 경로와 연결한다.
6. 신빙성의 한계
   - Haru는 공식 의료 검사나 진단 도구가 아니며, 자체 임상 검증 전에는 효과를 단정하지 않는다.
7. 향후 검증 계획
   - 전문가 자문, 파일럿 테스트, 익명화된 반복 사용 데이터 분석, 사용자/보호자 인터뷰.
8. 참고문헌
   - 로컬 manifest와 원문 URL을 기준으로 추적 가능하게 작성한다.

## 10. 보고서 작성 원칙

- 모든 의학·인지 관련 주장은 로컬 자료 또는 새로 확인한 권위 자료에 연결한다.
- 공식 검사명은 배경 설명에만 제한적으로 사용하고, Haru 기능명이나 점수명으로 사용하지 않는다.
- 구현 신빙성은 “임상 효과 입증”이 아니라 “권위 있는 인지 영역을 참고해 원본 루틴으로 설계했고, 비진단·반복 관찰·대화 지원 목적에 맞게 구현했다”는 방향으로 설명한다.
- 연구 자료가 닫힌 논문, 상업 검사, 공식 양식인 경우 본문에 내용을 복제하지 않는다.
- 국내와 일본 맥락을 모두 포함하되, 확인되지 않은 통계는 작성하지 않는다.
- 최종 보고서는 한국어로 작성하되, 논문 제목, 기관명, URL, 파일명은 원문 표기를 허용한다.

## 12. 중단 규칙

다음 상황에서는 추측하지 말고 사용자에게 확인한다.

- 보고서가 제출용인지 내부용인지 불명확한 경우.
- 특정 문헌의 원문을 확인하지 못했는데 강한 의학적 주장을 넣어야 하는 경우.
- 공식 검사 문항, 채점표, 절단점, 원문 자극을 앱이나 보고서에 넣으라는 요구가 있는 경우.
- 개인정보, 가족 공유, 보호자 리포트에서 비공개 기억 노출 위험이 있는 경우.
- 대용량 참고자료, 논문 PDF, 데이터셋, 신청서 문서를 Git에 포함해야 하는지 불명확한 경우.
- Vercel 배포, Git push, 신청서 산출물 커밋 범위가 섞이는 경우.

다음 상황에서는 명시된 가정으로 진행할 수 있다.

- 보고서 용도가 불명확하지만 사용자가 “일단 작성”을 지시한 경우: Markdown 초안을 기본값으로 한다.
- 분량이 불명확한 경우: 5~7쪽 분량의 한국어 보고서 초안으로 한다.
- 일본 통계가 아직 확인되지 않은 경우: 일본 관련 문헌 조사 TODO를 남기고 국내·국제 근거만 본문에 사용한다.
- 기능 개선 중 디자인 판단이 필요한 경우: `design.md`와 기존 Haru UI 원칙을 우선한다.
