1. 발표의 단일 목표
======================================================================

발표가 끝났을 때 심사위원이 내려야 할 판단
- Haru는 아이디어 단계의 앱이 아니라 실제 물리 버튼과 화면이 연동되는 고령자용 키오스크이다.
- 20명 지인 기반 사용 흐름 확인에서 발견한 접근성 장벽을 큰 화면·2×2 물리 버튼·명확한 음성 상태로 해결했다.
- 사용자의 말을 이해하고, 남겨진 기억 근거를 다음 문항과 상담에 다시 쓰는 로컬 AI 구조까지 구현했다.
- 현재는 국내 현장 실증, 특허, 연구논문화, 기관형 사업화를 순서대로 실행할 수 있는 단계이다.
- 한국 실증을 기반으로 일본 문화·운영 환경에 맞춘 현지 실증까지 확장할 팀 구성을 갖췄다.

한 문장 결론
- “Haru는 네 개의 버튼으로 어르신의 어제 이야기를 오늘의 문항과 다음 대화로 잇는 기관 설치형 기억 루틴 키오스크이다.”

발표 서사
- 실물 작동 증거 → 한·일 고령사회 문제 → 20명 사용 확인 → 2×2 해결 → 하루 사용 경험 → 기억 데이터의 가치 → 음성 이해 원리 → 기억 재사용 원리 → 보호자·기관 가치 → 사업모델 → 국내·일본 로드맵 → 팀과 투자 요청

본문에서 하지 않을 것
- STT 모델 세부 수치, 음향 전처리 상수, API 목록, 데이터베이스 스키마 설명
- RAG 모델명, 벡터 검색 구현, Neo4j·SQLite 상세 비교
- 모델명·포트·임계값·테스트 개수·영문 약어를 본문 핵심 메시지로 사용하는 구성
- 합성 시뮬레이션 수치의 실제 사용자 성과화
- 공식 인지검사·진단 도구처럼 보이는 표현
- 증빙 없는 복지관 수, 특허 등록, IRB 승인, 효과 입증 주장

본문 기술 표현 규칙
- 한 기술 슬라이드당 `사용자 문제 → 해결 원리 → 제품 가치`만 제시
- 기술명은 작은 보조 라벨로만 사용하고 발표 문장은 쉬운 한국어로 구성
- 모델·처리 상수·데이터 구조·API·테스트 수치는 Appendix에서만 제시

2. 근거 통합 원칙
======================================================================

최신 제품·사업 방향의 기준

- 발표자료/개발계획서_오가사.pdf
- 두 문서의 40쪽 PDF와 HWPX 표·본문을 각각 확인해 제품 정의, 기관 설치형 운영, B2B·B2G, 한국·일본 실증, 팀 역할을 발표의 중심 전략으로 사용한다.

현재 구현 상태의 기준
- 저장소 README.md, backend/README.md, rag_backend/README.md
- raspberry-pi-demo/README.md와 실제 7일 문항 데이터
- 개발계획서의 “STT·RAG 개발 중” 문구보다 현재 저장소 구현 상태를 우선한다.
- 단, Raspberry Pi 키오스크와 시설 내 로컬 GPU STT·RAG는 아직 하나의 현장 제품으로 완전 통합된 상태가 아니다.

기술 참고 PPTX의 사용 원칙
- Haru_음성UX_사전검증_발표자료.pptx: UX 개입과 실증 설계 참고. 모든 수치는 합성 시뮬레이션이다.
- STT.pptx: 기술 기획과 외부 벤치마크 참고. Haru 고령자 정확도 결과가 아니다.
- elder_memory_graph_business_insert_3slides.pptx: 개인 기억 RAG의 개념과 사업 가치 참고. 외부 참고 UI를 실제 Haru 화면처럼 사용하지 않는다.

상태 우선순위
- 실제 구현 → 사용자 제공 실제 진행 상태 → 최신 개발계획서 → 기존 발표자료 → 향후 계획

슬라이드의 역할

화면에 보일 핵심 수치

- 한국 2025년 추정 치매 환자: 97만 명, 2026년 100만 명 초과 전망

문제 구조

- 기관: 대면 문답·수기 기록·반복 확인에 의존
- 결과: 오늘의 기분·장소·활동이 다음 상담 전에 사라짐

이미지 구성

- 오른쪽 60%: 대면 문답 → 수기 기록 → 다음 근무자의 반복 확인 → 정보 공백

발표 핵심 문장

- 긴 쉼 미절단·전체 발화 no-speech gate
- confidence=null, token timestamp
- 25MB·65초 제한, GPU 1 active + 2 pending
- durable retry와 실패 비차단
- 기본 자동화 테스트 54건 통과, 실제 GPU/model smoke 1건 미실행

A09. 개인 기억 RAG의 근거 데이터 구조
부제목: 불변 원문·Evidence·의미 검색·명시 관계·삭제
- immutable canonical snapshot
- 모든 선택·순서·음성 응답의 Evidence
- multilingual-E5 검색
- 음성의 명시적 annotation에서만 entity·relation 생성

- 민감 transcript 기본 제외와 삭제 흐름

A10. 근거 QA와 다음 문항 생성
부제목: no_answer·requires_review·Galaxy 투영·구현 경계
- /timeline, /graph, /qa, /questions/generate의 기능 흐름
- 근거 부족 시 no_answer

- RAG 테스트 51건 통과, 실제 E5가 아닌 deterministic fake encoder 사용

A11. NFC 운영과 개인정보 보호

A13. 한국·일본 현장 실증 설계

A14. 특허·IRB·팀 역할과 증거 상태
