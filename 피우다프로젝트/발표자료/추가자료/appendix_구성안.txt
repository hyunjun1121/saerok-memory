작성 2026-08-17 / 확정 사항: 총 9장, RAG 2장, 하드웨어 도면 포함, '이 장이 증명하는 것' 라벨 없음

전체 구성: 본문 12장 + 부록 9장 = 21장


═══════════════════════════════════════════════════════════════
설계 원칙
═══════════════════════════════════════════════════════════════
1. 한 장 = 한 가지 질문에 대한 답. 슬라이드 제목이 곧 그 질문의 답이 되게 쓴다.
2. 본문에서 못 한 이야기만 담는다. 본문 반복 금지.
3. 모든 수치·상수·모델명은 리포지터리 실설정에서 추출한 것만 쓴다.
4. 아직 측정하지 않은 것은 '다음 측정 항목'으로 분리해 같은 장 안에 둔다.
   (부인 문구는 화면에 쓰지 않고 발표자 노트로만 유지 — 기존 방침 유지)

A04 · 어르신 발화를 살리는 입력 처리와 런타임 계약
═══════════════════════════════════════════════════════════════
답하는 질문 : "어르신 목소리가 작고 느린데 그건 어떻게 처리하느냐"
핵심 메시지 : 긴 쉼을 잘라내지 않는다는 선택. 실패가 하루 루틴을 멈추지 않게 만든 계약.

              우: 무응답 처리 규칙 4줄
              하단: 검증된 범위(자동화 54개) / 다음 측정 항목 / 외부 전처리 연구 참고 이미지

              backend/app/config.py max_upload_bytes, STT_MAX_AUDIO_SECONDS=65
              backend/app/admission.py max_active=1, max_pending=2
              backend/tests/ 54개 (admission 2 + audio 18 + main 26 + stt 8)

A05 · 개인 기억을 무엇으로 저장하고 어떻게 찾아내는가
═══════════════════════════════════════════════════════════════
답하는 질문 : "개인화한다는데 대체 뭘 저장하고 뭘 근거로 찾느냐"
핵심 메시지 : 등록 정보(불변)와 응답 근거(누적)를 분리해 SQLite 한 곳에 남기고,
              말한 것만 관계로 만든다. 모델이 추측한 관계는 만들지 않는다.
화면 구성   : 상단 5계층 흐름
                 SQLite(단일 원장) → Canonical Snapshot(불변 등록정보)
                 → Evidence(모든 응답 근거) → multilingual-E5(의미 검색) → Neo4j(선택 미러·기본 off)
              좌: 저장 원칙 5줄
              중: 관계 생성 규칙 4줄 — 명시 annotation 있을 때만 entity/relation 생성
              우: 민감 정보 · 삭제 4줄
              하단: 자동화 검증 범위 + 아직 평가 안 한 것(검색 적합도)
근거        : rag_backend/app/core/config.py
                database_url = sqlite:///data/haru.db
                embedding_model_id = "intfloat/multilingual-e5-small" (로컬 경로 로드)
                neo4j_enabled = False
              rag_backend/app/services/extraction.py, ingestion.py, deletion.py
현재 상태   : 기존 A08 계승 + 검색 부분 흡수 (2장 결정에 따라 통합)

                 ① 저장된 Evidence 조회 (결정적 QA · 근거 못 찾으면 no_answer)

                 ③ 검토 통과분만 다음 일차 화면에 노출
              좌하: 생성형 LLM의 자유 답변 경로가 없다는 구조 설명
              우하: 자동화 51개 통과 범위 / 다음 평가 항목 4줄
              (Galaxy 3D 투영은 이 장 우측 하단에 두 줄로만 언급, 별도 장 만들지 않음)
근거        : rag_backend/app/services/qa.py, query.py, question_generator.py
              rag_backend/tests/ 51개 (embedding 4 + ingestion_hardening 22 + market_locale 5 + pipeline 20)
              rag_backend/app/api/routes.py (3D 투영 API)
현재 상태   : 기존 A09 계승, 파이프라인 도해로 재구성

═══════════════════════════════════════════════════════════════

              원 용어 대응은 발표자 노트에 유지.
근거        : rag_backend/app/services/deletion.py (sqlite_deleted · neo4j_deleted 동시 반환)
              결선발표_요구사항.txt 5행·11행, 보안특강 자료(원문 대조 후 사용)
